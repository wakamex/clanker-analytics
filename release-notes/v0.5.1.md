clanker-analytics now reads quota for every provider from [clanker-usage](https://github.com/wakamex/clanker-usage), records every Claude account, and paces each account over the time it was actually used.

- Quota and plans come from clanker-usage's usage-v1 documents, the same for Claude, Codex, Antigravity, Gemini CLI and Z.ai. clanker-analytics depends on `clanker-usage>=0.4.0` instead of the five per-tool usage packages. History recorded with the older packages is renamed to the new window and account names when the database opens, so each window continues as one series ([`5e8ddea`](https://github.com/wakamex/clanker-analytics/commit/5e8ddea65bffa36b120a5062f05a6f61fa5184af), [`8683617`](https://github.com/wakamex/clanker-analytics/commit/8683617d1994c2f59c753fed359334410fee1ae0)).
- `record-quota` records every Claude account that clanker-usage has cached, not only the default login, so a second account used through `CLAUDE_CONFIG_DIR` gets history too ([`baf2882`](https://github.com/wakamex/clanker-analytics/commit/baf28822c2952ecd2659b24bdddcad6f1e067308)).
- `pace` counts an account as in use only while its quota rose, rather than whenever it had samples. In `pace --json`, `logged_in_hours`, `logged_out_buckets` and `logged_out_since` are renamed `active_hours`, `inactive_buckets` and `last_used_at`; update scripts that read them ([`baf2882`](https://github.com/wakamex/clanker-analytics/commit/baf28822c2952ecd2659b24bdddcad6f1e067308)).
